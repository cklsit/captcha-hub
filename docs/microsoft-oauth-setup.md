# 配置 Microsoft 账户登录（OAuth 2.0）

微软自 2022 年起停用了 IMAP 的密码登录。`outlook.office365.com` 会在 `CAPABILITY`
里直接声明 `LOGINDISABLED` 并只接受 `AUTH=XOAUTH2`，登录尝试会被明文拒绝：

```
S> * CAPABILITY IMAP4 IMAP4rev1 AUTH=XOAUTH2 LOGINDISABLED ...
C> a2 LOGIN you@outlook.com ********
S> a2 NO Basic authentication is disabled.
```

网页密码、应用密码都不行，唯一出路是 OAuth 2.0。

本应用提供两种登录方式，**优先使用第一种**：

| 方式 | 体验 | 前提 |
| --- | --- | --- |
| **重定向登录**（推荐） | 点一次按钮 → 自动打开浏览器 → 在微软自己的页面登录 → 自动完成。**无需填写邮箱地址，也无需输入任何验证码** | 需在 Azure 应用里注册回调地址 `http://localhost`（第 4 步） |
| **设备码登录**（兜底） | 点按钮 → 打开页面 → **手动输入一个短码** | 无需任何额外配置 |

没配回调地址也不会坏：应用会在打开浏览器**之前**先探测一次，发现没注册就自动改用设备码方式，并在界面上提示你如何开启更省事的那条路。

## 一次性注册（约 5 分钟，免费，不需要 Azure 订阅）

### 1. 进入应用注册

打开 <https://portal.azure.com>，用你的 Microsoft 账户登录（个人账户即可）。
顶部搜索框输入 **Microsoft Entra ID**（旧称 Azure AD）并进入。

左侧菜单 → **应用注册** → **新注册**。

### 2. 填写注册信息

| 字段 | 填什么 |
| --- | --- |
| 名称 | 随意，例如 `Mail Hub` |
| 支持的帐户类型 | ⚠️ 选**第三项**：「任何组织目录中的帐户…和个人 Microsoft 帐户」 |
| 重定向 URI | **留空**（设备码流程不需要） |

> 第二项选错的话，个人 `outlook.com` 账户会登录失败。这点最容易踩坑。

点 **注册**。

### 3. 复制 Client ID

注册完成后页面会显示 **应用程序(客户端) ID**，形如
`1a2b3c4d-5e6f-7a8b-9c0d-1e2f3a4b5c6d`。
**这就是要填进本应用的「Application (client) ID」。**

### 4. 配置「身份验证」页（两项，都在同一页）

左侧 **身份验证**，做两件事：

**(a) 打开公共客户端流（必做）** — 拉到最下 **高级设置** →
**允许公共客户端流** 设为 **是**。

> 不开这一步会报 `invalid_client` / `AADSTS7000218`。

**(b) 添加回调地址（推荐，用于免输码的一键登录）** — 在 **平台配置** 中：

1. 点 **添加平台** → 选 **移动和桌面应用程序**
2. 在「自定义重定向 URI」里填 **`http://localhost`**
3. 点 **配置**

最后 **保存**。

> 这一步是微软官方对桌面应用的推荐做法（文档里明确列了 Node.js / Electron 的情形）。
> 跳过它不会报错，只是会退回设备码方式、需要你手动输一次短码。
> 应用会自动探测并择路，所以**先跳过、以后再补也可以**。

### 5. 添加 IMAP / SMTP 权限

左侧 **API 权限** → **添加权限**：

1. 选 **我的组织使用的 API** 标签页
2. 搜索 `Office 365 Exchange Online` 并点进去
   （若这里找不到，改走 **Microsoft Graph** → 委托的权限 → 搜 `IMAP` / `SMTP`）
3. 选 **委托的权限**，勾选 **IMAP.AccessAsUser.All**（收信）与 **SMTP.Send**（发信）
4. **添加权限**

> **只收信**可以只勾 `IMAP.AccessAsUser.All`；但本应用不只是收验证码，还要能**发信**，
> 因此推荐一并勾上 **SMTP.Send**。若你此前只授权了 IMAP，**首次发信**时应用会提示
> 「需重新授权以启用发信」，此时回到本应用重新点一次「使用 Microsoft 账户登录」即可补齐 scope。

个人账户到此即可——登录时会在授权页现场征求你的同意。

> **工作/学校账户（Microsoft 365）** 额外需要管理员在「API 权限」页点击
> **代表 <组织> 授予管理员同意**，否则登录可能被拒绝。

## 在应用里添加账户

1. 邮件页 → **管理账户** → **新增账户**
2. **认证方式** 选 **「Microsoft 账户登录（Outlook / Hotmail / M365）」**
   —— 服务器地址会自动填成 `outlook.office365.com:993`，不用管
3. 粘贴注册时复制的 **Application (client) ID**；租户保持 `common`
4. 点 **「使用 Microsoft 账户登录」**

接下来分两种情况，**都不需要你填写邮箱地址**：

- **已配置回调地址**：浏览器自动打开微软登录页 → 用你的 Microsoft 账户登录 →
  回到应用即为「登录成功」，**邮箱地址已自动填入**
- **未配置回调地址**：界面会给出一个形如 `ABCD-EFGH` 的设备码 →
  按提示打开 <https://microsoft.com/devicelogin> 输入该码完成登录

5. 看到「登录成功，邮箱地址已自动填入」后，点 **保存**

> 登录所用的邮箱地址由微软在令牌里返回，应用据此自动填写，因此**你永远不需要手打邮箱地址**。
> 如果字段仍是空的，说明微软没有返回地址声明，此时才需要你手动补填。

## 安全说明

- 访问令牌与刷新令牌**只存在于主进程**，不经过渲染层，也不会显示在任何界面上
- 两者落盘前都加密（`safeStorage` 优先，降级 AES-256-GCM）
- 访问令牌过期前会自动静默刷新，你无需重复登录
- 应用会记录服务器**实际授予的 scope**；缺少 `SMTP.Send` 时首次发信会提示重新登录
- 导出备份时**不会**包含令牌；恢复备份后需要重新授权一次
- 把账户的认证方式改回「密码 / 授权码」会**清除**已保存的令牌

## 撤销授权

在 <https://account.microsoft.com/consent> 或 Microsoft Entra ID 的
「企业应用程序」中可以随时撤销本应用的访问权限。

## 排错

| 现象 | 原因 |
| --- | --- |
| `invalid_client` / `AADSTS7000218` | 第 4(a) 步「允许公共客户端流」没开 |
| `AADSTS700038` | Client ID 填错或不是有效的应用 ID |
| `unauthorized_client` / 授权页报错 | 第 2 步账户类型选成了「仅此组织目录」 |
| 登录成功但同步报 `AUTHENTICATE failed` | 第 5 步的 IMAP 权限没加，或工作账户缺管理员同意 |
| 收信正常但**发信**提示「需重新授权」 | 第 5 步的 `SMTP.Send` 权限没加；补齐后重新登录一次 |
| 界面提示「尚未注册重定向地址」并给了设备码 | 第 4(b) 步的回调地址没加。按设备码方式仍可正常登录；想免输码就补上 `http://localhost` |
| 浏览器打开了但页面报 `AADSTS50011` / `AADSTS500113` | 回调地址没注册或注册位置不对：必须加在 **移动和桌面应用程序** 平台下，且填 `http://localhost`（不要带端口、不要带路径） |
| 一直在等浏览器回调，约 45 秒后自动切成设备码 | 浏览器里没有完成登录，或登录用了别的浏览器/窗口。直接用给出的设备码即可 |
| 登录页正常但没有任何反应 | 检查是否有代理/安全软件拦截了 `http://localhost` 的回环请求 |
| `服务端未启用 IMAP` | 到 Outlook.com 网页版「设置 → 邮件 → 转发和 IMAP」打开 IMAP |

> 说明：应用在打开浏览器**之前**会先探测一次授权地址，只有在能确定是「回调地址未注册」时
> 才会改走设备码；其他不确定的情况一律按可用处理，宁可事后兜底也不阻断本可成功的登录。
